# PROB-NNN — Краткое название проблемы

## Метаданные

- **ID:** PROB-NNN
- **Название:** …
- **Обнаружена:** YYYY-MM-DD или «точная дата неизвестна»
- **Документирована:** YYYY-MM-DD
- **Компонент / подсистема:** …
- **Стек и версии:** …
- **Severity:** Critical / High / Medium / Low
- **Status:** Investigating / Fixed / Pending Verification / Verified
- **Связанные файлы:** `path/to/file`

## Контекст

Какой функционал разрабатывался, как система должна была работать и что происходило фактически.

## Симптомы

Точные сообщения, HTTP-статусы, наблюдаемое поведение и известная воспроизводимость. Не включать секреты и персональные данные.

## Шаги воспроизведения

## Root Cause (первопричина)

Разделить доказанные факты и остающиеся гипотезы. Указать диагностические данные и код, которые подтверждают вывод.

## Архитектурный / функциональный недостаток

Почему существующая граница ответственности, протокол или проверка допустили проблему.
